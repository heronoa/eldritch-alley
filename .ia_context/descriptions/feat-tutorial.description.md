---

### 1. What this MR delivers

The whole of M3.5: a nine-card sequence that opens over the title on a browser that has never seen it, is skippable and readable in either direction, is remembered in `localStorage`, and can be reopened at any time from a "Como jogar" link the footer grew for it. The cards are three of story (the incident, the admission test, the squad) followed by six of how-to-play (the grid and its height, the initiative queue, moving and attacking, ammunition/energy and reloading, cover with the hit-chance badge, abilities), which is the split [`.ia_context/plans/onboarding.index.md`](../plans/onboarding.index.md) settled and ROADMAP § M3.5 describes. A first-time visitor reads it before the call to action is usable — the overlay's backdrop covers the whole screen while it is up, and Tab is answered by the overlay itself, so neither mouse nor keyboard reaches `#cta` behind it; a returning visitor gets a `hidden` box and nothing else. Nothing in the connection path is touched: `connect-flow.ts`, `press()` and the `Session` are exactly as they were, so the sequence is a layer over the title rather than a step of it.

**Three divergences from the approved plans, named rather than smoothed over.** First, m2 planned `onboarding.ts` as the file that holds the rules with a jsdom test (`onboarding.test.ts`) over them; it shipped instead as a pure rules module, `overlay.ts`, with the plan's seven jsdom scenarios re-expressed as Node tests, and `onboarding.ts` reduced to DOM wiring — the split `title-screen.lesson.md` records and the one the rest of this client already follows. Every rule the plan asked to be verified is verified; what changed is that the checks read as pure functions instead of as a real document, and `onboarding.ts` is consequently the one file of the feature no test executes. Second — and not foreseen by any plan — the language switcher had to be moved out of `.title`, because the overlay made it unreachable: the switcher is how the cards get read in the right language, and it was ordered *under* the overlay no matter what `z-index` it was given inside a `position: fixed` ancestor. That correction reached into `title.css` and `index.html`, which both m2 and m3 had listed as out of scope, and is recorded as §7 of the m3 plan. Third, the squad card named the base classes of `pitch.md`'s opening line ("soldados, iniciados e adeptos") where the match actually fields the advanced ones; the text now says sniper, wizard and priest, which is what `backend/game-server/src/map.ts` musters.

**One known gap, recorded and not fixed:** the focus trap that makes the overlay a real `aria-modal` dialog also keeps a keyboard-only player from reaching the switcher while the first card is up — the way out is Skip (or reading to the end) and reopening from the footer. Extending the trap over the language buttons is a design decision (a true modal dialog, or reachable chrome) and is left to the owner; it is written down in §7 of the m3 plan rather than left to be rediscovered in review.

Verified at the head of this branch: `npm test -w @eldritch-alley/frontend` 887/887 in 68 files; `npm run typecheck` and `npx tsc -p frontend/tsconfig.json --noEmit` both clean; `npm run build -w @eldritch-alley/frontend` passes (entry 220.23 kB / gzip 70.87 kB, CSS 5.29 kB / gzip 1.66 kB, match chunk 1,610.22 kB / gzip 380.08 kB, with the same sub-500 kB chunk warning the project has carried since M2). The onboarding adds roughly 9 kB to the entry chunk.

### 3. What this MR does not deliver

Deferred by the plans themselves, with where each one is going:

- **A guided, interactive tutorial over the real board** — tooltips, locked actions, anything that participates in a live match. Decision D2 of the index: the sequence is static, and a guided pass is a future iteration if post-delivery feedback still asks for one.
- **Persisting the flag per account, and any server-side record of who has read the sequence.** M4 owns accounts; this flag is the browser's alone (D4).
- **Illustrations** — a stamp of its own, an icon per topic. The cards are text, like the rest of the title today.
- **End-to-end tests.** The project runs Vitest only; m2 recorded opening this front as out of scope.
- **Extending the focus trap to the language buttons**, so a keyboard-only player can switch language while the first card is up. Recorded as a gap, left to the owner (§1 and m3 plan §7).

### 4. Notes for the reviewer

- **The stacking-context fix is the one part of this diff that was settled in a browser and not by reading.** The `z-index` alone did not solve it, and the reason is not visible in the CSS: `elementFromPoint` in the switcher's own corner, with the sequence open, landed on `.onboarding` even with `z-index: 2` on `.lang`, and only landed on the button once the switcher became a sibling of `.title`. `layers.test.ts` holds the numbers and the structure that makes them count — it cannot hold the pointer, which is the browser's to confirm. If you re-check one thing manually, check this.
- **The wording of the nine cards and of the four controls is unreviewed by the owner.** Nothing in the test suite pins a sentence (deliberately — `copy.test.ts` says so); the tests hold that every line exists, is non-empty, and follows the language. That leaves the copy itself open, and it is the part of this MR a player actually reads.
- **One contrast value is below the floor on purpose, and it is recorded rather than hidden.** The disabled Back button on the first card is `--muted` at `opacity: 0.72`, about 3.79:1; WCAG exempts a disabled control and the dimming is the entire cue. `contrast.test.ts` asserts the 3.79 so it cannot drift unnoticed. Raising it means another way of saying "disabled", which is a look change rather than a fix.
- **`catalog.test.ts` now fails if any `onboarding.*` key is untranslated in `en-US`**, on top of the title's own block. Adding a tenth card means writing its two lines twice; that is the intended cost.
- **This branch forked before the M3.5 plans existed on `develop`**, so the plan files travel in this diff. They are documentation — no onboarding code from an earlier branch is being re-delivered here.
- **The four commits map one-to-one onto the milestones** (`bf7960b` m1 logic, `5694f9a` m2 integration, `7b8b341` m3 design, `f7b2195` review corrections), so `git log -p` is a usable reading order if you want to review the feature the way it was built rather than as one diff.
